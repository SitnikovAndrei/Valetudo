# Руководство по репозиторию

## Структура проекта

Репозиторий организован как npm workspace. В `backend/lib/` находятся интеграции с роботами, API и серверный код на Node.js. Тесты расположены в `backend/test/`, а тестовые данные — в каталогах `res/` рядом с ними. Интерфейс на React и TypeScript находится в `frontend/src/`, статические файлы — в `frontend/public/`, настройки сборки — в `frontend/vite.config.mts`. Документация Eleventy хранится в `docs/pages/`, общие изображения и файлы протоколов — в `assets/`, вспомогательные скрипты — в `util/`. Не добавляйте в исходники результаты сборки и локальную конфигурацию робота.

## Сборка, тестирование и локальная разработка

Используйте Node.js 22.12 или новее. Выполните `npm ci` в корне репозитория: команда установит зависимости всех workspace и применит патчи через `patch-package`.

- `npm run dev --workspace=frontend` — запускает Vite на порту 5173 с прокси к локальному серверу на порту 80.
- `npm run watch --workspace=frontend` — пересобирает `frontend/build` при изменении файлов для проверки через сервер Valetudo.
- `npm run start:dev --workspace=backend` — запускает сервер с конфигурацией `local/valetudo_config.json`.
- `npm run build --workspace=frontend` — собирает интерфейс.
- `npm run build --workspace=docs` — собирает сайт документации; `npm run serve --workspace=docs` запускает его локально.
- `npm run build` — собирает интерфейс и серверные бинарные файлы для поддерживаемых архитектур; этот процесс дольше обычного цикла разработки.

## Стиль кода и именование

В `backend/` придерживайтесь существующего стиля CommonJS, в `frontend/` — React и TypeScript. Правила ESLint требуют отступы в четыре пробела, двойные кавычки, точки с запятой, перевод строки в конце файла и расположение фигурных скобок в стиле 1TBS. Называйте классы и компоненты в PascalCase; для файлов следуйте соглашениям соседнего кода. Перед завершением изменений запускайте `npm run lint_all` и `npm run ts-check_all`. Скрипты `lint_fix` в workspace исправляют поддерживаемые нарушения автоматически.

## Тесты

Серверные тесты используют встроенные модули Node.js `node:test` и `node:assert`. Их файлы находятся в `backend/test/` и имеют суффикс `*_test.js`. При изменении поведения добавляйте точечные тесты и необходимые фикстуры, затем запускайте `npm run test --workspace=backend`. Для интерфейса отдельного тестового скрипта нет: проверяйте изменения линтером, TypeScript и сборкой. Числовой порог покрытия не задан.

## Коммиты и порядок участия

В истории используются короткие темы коммитов, например `fix(core): Improve forced gc condition`, `feat(ui): Analytics` и `docs: Flow`. По возможности указывайте подходящий тип и область изменения, а в теме описывайте его результат. Перед предложением изменений прочитайте `CONTRIBUTING.md`: сопровождающий прямо указывает, что не принимает pull request; это также закреплено в `.github/pull_request_template.md`. Не открывайте PR — сначала обсудите потенциально полезное изменение с сопровождающим.
