# Соответствие макета возможностям Valetudo

Эта таблица фиксирует соответствие элементов исходного концепта возможностям приложения и решения для [обновлённого прототипа](./preview.html). Прототип использует демонстрационные данные и не вызывает API. Обозначения: **готово** — поведение уже есть в приложении; **условно** — зависит от capability робота; **новое** — потребует дополнительной реализации. При переносе дизайна следует использовать существующие React-компоненты, хуки и проверки состояния, а не SVG и демонстрационные значения из макета.

## Карта и управление

| Элемент макета | Текущее соответствие | Что сделать при переносе |
| --- | --- | --- |
| План квартиры, робот, база, маршрут | **Готово:** [`LiveMapPage`](../src/map/LiveMapPage.tsx), [`LiveMap`](../src/map/LiveMap.tsx), `useRobotMapQuery`; карта загружается через `/robot/state/map` и обновляется через SSE. | Сохранить настоящий canvas и его слои, жесты, состояние загрузки, ошибки и повторную загрузку. Демо-SVG удалить. |
| Масштабирование | **Частично:** [`BaseMap`](../src/map/BaseMap.tsx) уже поддерживает перемещение и масштабирование мышью/касанием. | Привязать кнопки к тому же преобразованию карты; полноэкранный режим оформить отдельно. В прототипе кнопки меняют только масштаб демо-SVG. |
| «Этаж 1» | **Нового подтверждённого переключателя этажей нет.** В интерфейсе есть управление одной картой, её сброс и редактирование: [`MapManagement`](../src/options/MapManagement.tsx). | Убрать подпись либо добавить только после проверки поддержки нескольких карт у backend и конкретного робота. |
| Названия комнат и выбор комнат | **Условно:** `MapSegmentation`, [`SegmentActions`](../src/map/actions/live_map_actions/SegmentActions.tsx), `useCleanSegmentsMutation`. | Показывать режим лишь при поддержке capability; брать реальные ID и имена сегментов, выбирать их на карте и учитывать число проходов. |
| Уборка зоны | **Условно:** `ZoneCleaning`, [`ZoneActions`](../src/map/actions/live_map_actions/ZoneActions.tsx), `useCleanZonesMutation`. | Дать выделить/изменить зону на карте, передавать реальные координаты и допустимое число проходов. |
| «Весь дом» и «Начать уборку» | **Условно:** `BasicControl`, [`BasicControls`](../src/controls/BasicControls.tsx), `useBasicControlMutation` с командой `start`. | Учитывать состояние робота, показывать Resume при продолжении и подтверждать запуск всего дома при незавершённом действии на карте. Прототип меняет только локальное состояние. |
| «Вернуть на базу» | **Условно:** `BasicControl`, команда `home` в [`BasicControls`](../src/controls/BasicControls.tsx). | Сохранить ограничения по состоянию, индикацию выполнения и обработку ошибки. Также вернуть в новый дизайн существующие Pause и Stop. |
| Имя модели, состояние, заряд | **Готово:** `useRobotInformationQuery`, `useRobotStatusQuery`, `useRobotAttributeQuery(BatteryState)`; см. [`RobotStatus`](../src/controls/RobotStatus.tsx). | Показывать реальные значения, несколько батарей, загрузку/ошибку. «Робот в сети» выводить только при достоверном состоянии соединения. |
| «42 мин», «34 м²», «Последняя уборка» | **Частично:** `CurrentStatistics` и `TotalStatistics` дают доступные роботу показатели; см. [`CurrentStatistics`](../src/controls/CurrentStatistics.tsx). | Показывать только реально доступные типы статистики. Не называть их «последней уборкой» без отдельной истории сеансов. |
| «Обновлено 2 мин назад» | **Частично:** запрос карты и SSE существуют. | Считать время по фактическому обновлению данных; при обрыве/ошибке не показывать фиктивную свежесть. |
| «Локальное подключение» | **Новый индикатор для этого места.** Текст макета статичен. | Отдельно определить проверяемый источник статуса и состояния offline; не выводить зелёную точку без проверки. |
| Дата, приветствие, «Анна» и аватар | **Только макет:** дата, имя и аватар захардкожены; профиль пользователя для этого экрана не найден. | Дату брать из локального времени, персонализацию убрать или явно добавить источник имени. Не показывать фиктивного пользователя. |
| Меню «···» | **Только макет:** кнопка не открывает меню. | Задать конкретные действия или убрать элемент; не оставлять пустую кнопку в рабочем UI. |

## Настройки и навигация

| Элемент макета | Текущее соответствие | Что сделать при переносе |
| --- | --- | --- |
| Светлая/тёмная тема | **Готово:** [`App`](../src/App.tsx) хранит `palette-mode`, учитывает системную тему; переключатель есть в [`ValetudoAppBar`](../src/components/ValetudoAppBar.tsx). | Проверять карту, все разделы и состояния в обеих темах. |
| «Мощность всасывания» | **Условно:** `FanSpeedControl`, [`PresetSelection`](../src/controls/PresetSelection.tsx), `usePresetSelectionsQuery`/`usePresetSelectionMutation`. | Показывать пресеты именно этого робота. Сейчас селект макета меняет только значение в браузере. |
| «Режим уборки по умолчанию» | **Частично:** есть `OperationModeControl` и разовые действия полной/комнатной/зональной уборки. | Уточнить семантику: режим работы робота ≠ сохранённый тип следующей уборки. Для последнего понадобится отдельное локальное или серверное состояние. |
| «Повторная уборка» | **Частично:** число проходов поддерживают действия уборки комнат/зон и таймеры, если робот разрешает; см. [`SegmentActions`](../src/map/actions/live_map_actions/SegmentActions.tsx), [`ZoneActions`](../src/map/actions/live_map_actions/ZoneActions.tsx). | Заменить общий переключатель на число проходов у конкретного действия; не обещать глобальный параметр для всех режимов. |
| «Тихие часы» | **Условно:** `DoNotDisturb`, [`DoNotDisturb`](../src/robot/capabilities/DoNotDisturb.tsx), query/mutation конфигурации. | Показать реальные часы и кнопку применения; убрать подпись «Не запускать уборку»: эффект DND зависит от модели и прошивки. |
| «Уведомления» | **Частично:** [`ValetudoEvents`](../src/components/ValetudoEvents.tsx) показывает события и позволяет взаимодействовать с ними. | Переключатель доставки уведомлений не найден. Нужны выбранный канал и его настройка; иначе убрать переключатель. |
| «✓ Сохранено» | **Только макет.** Изменения демонстрационных контролов не отправляются роботу. | Показывать статус сохранения после успешной mutation, а также ошибки и незавершённые изменения. |
| «Расписание» | **Готово:** [`Timers`](../src/valetudo/timers/Timers.tsx), `/valetudo/timers`. | Связать навигацию с существующим разделом; сохранить создание, изменение, запуск и удаление таймеров. |
| «Карта и зоны», «Подключения», «Система» | **Готово как группы разделов:** [`MapManagementOptionsRouter`](../src/options/MapManagementOptionsRouter.tsx), [`ConnectivityOptionsRouter`](../src/options/ConnectivityOptionsRouter.tsx), [`RobotOptionsRouter`](../src/options/RobotOptionsRouter.tsx). | Настроить реальные маршруты и вложенную навигацию. Прототип показывает их состав, но не открывает рабочие страницы. |
| «История» | **Нет эквивалента истории отдельных уборок.** Есть суммарная статистика `/robot/total_statistics` и журнал `/valetudo/log`. | Назвать пункт «Статистика»/«Журнал» либо добавить модель и хранение истории уборок. |

| Элемент макета | Текущее соответствие | Что сделать при переносе |
| --- | --- | --- |
| Карта и панель действий | **Готово:** [`HomePage`](../src/HomePage.tsx) размещает настоящие карту, статус и контролы вертикально на узком экране. | Сохранять жесты карты, выбор комнат/зон и доступность действий при последующих изменениях. |
| Статус, заряд, быстрый запуск | **Как на десктопе:** те же hooks и `BasicControl`/`MapSegmentation`/`ZoneCleaning`. | Использовать общий источник состояния и те же правила доступности/подтверждения, чтобы мобильный экран не расходился с десктопом. |
| Нижняя навигация «Главная / История / План / Ещё» | **Частично:** маршруты есть через [`AppRouter`](../src/AppRouter.tsx), но пункты макета не являются ссылками. | «История» переименовать или реализовать, «План» вести к таймерам, «Ещё» открыть все оставшиеся разделы. |

## Что обязательно сохранить при полной переработке

Меню действующего приложения существенно шире трёх экранов: расходники, ручное управление, суммарная статистика, камера, редактирование сегментов/запретных зон/аннотаций, настройки подключения (авторизация, MQTT, NTP, Wi-Fi), параметры робота, таймеры, журнал, обновление, системная информация и справка. Список маршрутов и проверки `Capability`/конфигурации устройства находятся в [`ValetudoAppBar`](../src/components/ValetudoAppBar.tsx). В прототипе эти разделы представлены в меню «Все разделы» и категориях настроек; отдельные экраны для них не прорисованы.

**Вывод для реализации:** без изменений backend можно перенести компоновку, темы и уже существующие действия/настройки с условным показом по capabilities. Историю отдельных уборок, общий режим «по умолчанию», настройку доставки уведомлений и переключение этажей нельзя считать существующими функциями без отдельной проработки контракта и хранения данных.

## Состояние прототипа

В [макете](./preview.html) есть сценарии с расширенными и базовыми возможностями робота, состояния базы, уборки, паузы, остановки, движения к точке и возврата, выбор области на демо-карте, обзор разделов и обе темы. Запуск требует выбрать область для комнат, зоны или точки. Все действия остаются локальной демонстрацией без вызовов API. История отдельных уборок, этажи, пользовательский профиль и настройка доставки уведомлений исключены, поскольку для них нет подтверждённого источника данных.
